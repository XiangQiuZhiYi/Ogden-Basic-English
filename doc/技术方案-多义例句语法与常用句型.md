## 1. 需求概述

### 1.1 范围调整

- 保留上一轮的“只看未学习”筛选。
- 取消“中文翻译为 Ogden Basic English”功能，不新增模型接口、翻译面板和联网依赖。
- 新增三项内容优化：
  1. 每个词按不同 Basic English 教学义项提供对应例句。
  2. 完善语法规则，为每条规则增加解释、正例、限制和常见错误。
  3. 新增“常用句型”模块，以用户提供的六类结构为起点，补全 18 个 operators 的高频组合和句子变换。

### 1.2 义项口径

“覆盖不同意思”推荐定义为：**覆盖该词在 Ogden Basic English 体系内需要掌握的核心义项、词性差异和结构差异，不收录普通英语词典中的全部历史义、专业义、俚语义和 Basic 不鼓励的动词化用法。**

例如：

- `light` 至少区分“光／灯”和“轻的”等 Basic 内必要义项，每个义项分别给例句。
- `right` 至少区分“正确的”和“右边的／向右”等结构差异。
- `answer` 在严格 Basic 造句中优先作为 thing，通过 `give an answer` 表达动作，不因为普通英语允许 `answer` 作动词就自动加入该用法。

若改成“覆盖现代英语词典全部义项”，内容规模、来源授权和审校成本都会显著扩大，也会削弱本项目作为受控英语学习页的边界。

### 1.3 现状审计

| 项目 | 当前状态 | 与新需求的差距 |
|---|---|---|
| 词条数量 | 850 | 数量正确 |
| 例句数量 | 每词固定 1 条，共 850 条 | 无法按义项分别展示 |
| 义项模型 | `zh/definition/definitionZh` 单值字段 | 没有 `senses[]`，无法表达一词多义 |
| 多义迹象 | 至少 199 条中文释义含分隔或并列语义标记 | 需要逐词人工判定，不可仅按标点拆分 |
| 人工审校 | 18 条核心用法已核验；其余 832 条处于不同程度待复核状态 | 内容增量必须继续展示审校状态 |
| 语法模块 | 12 张静态规则卡片 | 有框架，但解释、适用条件、反例和来源粒度不足 |
| 句型模块 | 无独立模块 | 部分句型散落在语法卡片中，不便按功能和 operator 查找 |
| 自动校验 | 可检查例句是否落在许可词汇范围 | 只支持单个 `example`，不支持多义项、多例句和句型数据 |

### 1.4 可行性结论

| 优化项 | 可行性 | 主要工作量 | 风险 |
|---|---|---|---|
| 只看未学习 | 高 | 小 | 交互与空状态 |
| 多义项例句 | 高 | 很大，主要是内容编辑与语言审校 | 义项边界错误、例句虽合法但不自然 |
| 完善语法 | 高 | 中高 | 规则过度简化或与普通英语混淆 |
| 常用句型模块 | 高 | 中 | 与语法模块重复、例句与 850 词边界不一致 |

整体不需要后端，仍可保持单文件离线发布。

## 2. 参考依据与内容原则

### 2.1 主要依据

- [C. K. Ogden, *Basic English: A General Introduction with Rules and Grammar*（Max Planck Institute 书目与公开文件）](https://www.mpi.nl/publications/item2366945/basic-english-general-introduction-rules-and-grammar)
- [Ogden 原课程 Step 1：operators、directions、基本词序](https://basicenglish.org/step-1/index.html)
- [Ogden 原课程 Step 2：be / put / take 与位置、移动组合](https://basicenglish.org/step-2/index.html)
- [Ogden 原课程 Step 3：come / go / get / give 与来源、去向](https://basicenglish.org/step-3/index.html)
- [Basic English 语法扩展规则摘要](https://zbenglish.net/sites/basic/rules.html)

### 2.2 编辑原则

1. Ogden 原始词目、分类和语法原则属于“来源事实”；中文解释、义项拆分和例句属于“项目编辑内容”，两者分别标注。
2. 每个例句必须证明它所属的具体义项或句型，不能只为了出现目标词。
3. 例句尽量只使用 850 核心词、许可词形、代词、数字和明确标记的特殊词。
4. 自动校验只能证明词汇边界和结构完整，不能替代语言学人工审校。
5. 不从受版权保护的教材批量复制例句；依据规则重新编写短例句，并记录来源类型。

## 4. 数据模型

### 4.1 词条与义项

```ts
interface BasicWord {
  id: string;
  word: string;
  ipa: string;
  category: string;
  subgroup: string;
  originalIndex: number;
  forms: string;
  senses: WordSense[];
  patternRefs: string[];
  reviewStatus: ReviewStatus;
  provenance: Record<string, string>;
}

interface WordSense {
  id: string;                    // 如 light-n-illumination
  partOfSpeech: string;          // Basic 体系中的教学词类
  glossEn: string;
  glossZh: string;
  scopeNoteZh: string;           // 使用边界、与普通英语的差异
  patterns: string[];            // 如 be-quality、give-thing-to-person
  examples: Example[];
  sourceRefs: string[];
  reviewStatus: ReviewStatus;
}

interface Example {
  en: string;
  zh: string;
  noteZh?: string;               // 该句如何体现义项或结构
  tokenStatus: 'pending' | 'valid';
  reviewStatus: ReviewStatus;
}
```

规则：

- 每个义项至少 1 条例句；容易混淆或结构差异明显的义项提供 2 条。
- 例句数不由标点机械决定；先判定义项，再写例句。
- 原有 `example/exampleZh` 在迁移期保留为兼容字段，所有词迁移完成后再删除。
- 一个义项若只在普通英语成立、但不属于本项目的 Basic 用法，应放入“普通英语提示”，不能当作 Basic 例句。

## 5. 页面与组件方案

### 5.1 词卡：按义项展示例句

词卡展开后由当前四宫格改为：

```text
词形与使用边界
├── 义项 1：英文释义 / 中文释义 / 范围说明
│   ├── 例句 1 + 中文 + 朗读
│   └── 例句 2 + 中文 + 朗读（需要时）
├── 义项 2：英文释义 / 中文释义 / 范围说明
│   └── 例句 1 + 中文 + 朗读
└── 相关句型：be + quality / get + quality
```

交互规则：

- 默认展开第一个核心义项，其余义项可折叠，防止词卡过长。
- 每条例句都可单独朗读。
- 点击“相关句型”跳转至句型模块并定位对应卡片。
- 学习状态仍以词为单位；第一阶段不细分到义项掌握度。

### 5.2 语法模块：从卡片摘要升级为课程式规则

推荐分为五章：

1. **系统基础**：四类词的作用、基本词序、thing 不任意动词化。
2. **operators**：18 个 operators 的形式、宾语和补语结构、时态承担方式。
3. **things 与 qualities**：冠词、复数、限定、比较、许可派生和复合词。
4. **句子操作**：陈述、否定、一般疑问、特殊疑问、命令、情态和时间。
5. **扩展表达**：directions、action-things、并列、从句、方式修饰和词汇边界。

每条规则统一展示：

- 一句话结论；
- 为什么这样表达；
- 公式；
- 适用条件与限制；
- 2–4 条正例；
- 1 条常见错误或普通英语对照；
- 关联句型。

### 5.3 新增“Patterns / 常用句型”Tab

导航调整为：

```text
850 Words | Grammar | Patterns | Communication
```

模块定位：

- `Grammar` 回答“为什么这样说、规则是什么”。
- `Patterns` 回答“我要表达某种功能，可以套哪个结构”。
- `Communication` 保留完整场景句，回答“在具体场景里怎么说”。

句型模块提供两个筛选维度：

- 按功能：状态、拥有、移动、取得、转移、造成、保持、许可、表达、感知、情态。
- 按 operator：18 个 operator 按钮。

第一阶段只做浏览、筛选、朗读和跨模块跳转；替换词造句练习可作为后续增强。

## 6. 常用句型补全方案

用户图片中的六类骨架保留，但需要补上主语、宾语位置、可选成分和 action-thing 结构。推荐整理为九个句型家族、约 30–40 个具体句型。

### 6.1 状态、身份与判断

| 句型 | 功能 | 示例 |
|---|---|---|
| `THING + be + THING` | 身份或归类 | `This is a book.` |
| `THING + be + QUALITY` | 性质或状态 | `The room is cold.` |
| `THING + be + DIRECTION` | 位置或关系 | `The book is on the table.` |
| `THING + seem + QUALITY` | 表面判断 | `The room seems cold.` |
| `THING + get + QUALITY` | 状态变化 | `The water gets cold.` |

### 6.2 拥有、经历、操作、感知与表达

| 句型 | 功能 | 示例 |
|---|---|---|
| `PERSON + have + THING` | 拥有 | `I have a question.` |
| `PERSON + have + ACTION-THING` | 经历或进行 | `We had a talk.` |
| `PERSON + do + ACTION-THING` | 做工作或一般操作 | `Do the work.` |
| `PERSON + see + THING` | 看见 | `I see the light.` |
| `PERSON + see + CONTENT` | 理解 | `I see your point.` |
| `PERSON + say + CONTENT` | 说出内容 | `Say it again.` |
| `PERSON + say + THING + to + PERSON` | 向某人表达 | `Say this to him.` |

### 6.3 移动与方向

| 句型 | 功能 | 示例 |
|---|---|---|
| `THING/PERSON + come/go + DIRECTION` | 直接方向 | `Come here.` |
| `THING/PERSON + come/go + from/to + THING` | 起点或终点 | `Go to the station.` |
| `THING/PERSON + come/go + through/across/over + THING` | 移动路径 | `Go through the door.` |

### 6.4 取得、拿取、给予与发送

| 句型 | 功能 | 示例 |
|---|---|---|
| `PERSON + get + THING + from + PERSON/PLACE` | 取得及来源 | `I got the book from him.` |
| `PERSON + take + THING + DIRECTION` | 拿走或移动 | `Take the book off the table.` |
| `PERSON + give + PERSON + THING` | 双宾语给予 | `Give me the book.` |
| `PERSON + give + THING + to + PERSON` | 强调被给予物 | `Give the book to me.` |
| `PERSON + send + PERSON + THING` | 发送给某人 | `Send me a letter.` |
| `PERSON + send + THING/PERSON + DIRECTION` | 送往某处 | `Send the letter to him.` |

### 6.5 造成、保持、放置与允许

| 句型 | 功能 | 示例 |
|---|---|---|
| `PERSON + make + THING` | 制作或产生 | `Make a copy.` |
| `PERSON + make + THING + QUALITY` | 造成状态 | `Make the room clean.` |
| `PERSON + keep + THING` | 保留 | `Keep the letter.` |
| `PERSON + keep + THING + QUALITY` | 维持状态 | `Keep the door open.` |
| `PERSON + put + THING + DIRECTION` | 放置 | `Put the book on the table.` |
| `PERSON + let + PERSON/THING + OPERATOR` | 允许 | `Let him go.` |

### 6.6 情态与将来

| 句型 | 功能 | 示例 |
|---|---|---|
| `PERSON + may + OPERATOR` | 许可或可能 | `You may go now.` |
| `PERSON + will + OPERATOR` | 将来或意愿 | `I will come tomorrow.` |

### 6.7 action-thing 高频组合

这一组是图片中没有完整展开、但对 Basic English 最关键的补充：

- `make + decision/change/attempt/copy`
- `give + answer/help/order/push`
- `have + talk/look/rest/experience`
- `take + walk/look/rest/measure`
- `do + work/damage`
- 具体组合必须逐条审校，不把任意 thing 与任意 operator 自由配对。

### 6.8 句子变换

- 一般疑问：`Do + PERSON + OPERATOR ...?`
- be 疑问：`Be + PERSON/THING + COMPLEMENT?`
- 否定：`PERSON + do not + OPERATOR ...`
- be / may / will 否定：直接在 operator 后加 `not`。
- 特殊疑问：`QUESTION WORD + QUESTION ORDER?`
- 命令：省略主语，直接以 operator 开头。

### 6.9 信息扩展

- `DETERMINER + QUALITY + THING`
- 主干后增加 `DIRECTION / PLACE / TIME / MANNER`
- 用 `and / but / or` 连接并列信息。
- 用 `because / if / though / while` 连接原因、条件、让步和时间关系。

这些结构不应与前七类平铺为“新的 operator 句型”，而应作为可以叠加到主干上的变换和扩展层。

## 7. 方法与校验变更

### 7.1 新增方法

| 方法 | 所在文件 | 作用 |
|---|---|---|
| `renderWordSenses(word)` | `src/js/app.js` | 按义项渲染释义、例句和关联句型 |
| `renderGrammar()` | `src/js/app.js` | 从 `grammar.json` 渲染章节与规则 |
| `renderPatterns(filters)` | `src/js/app.js` | 按功能或 operator 筛选句型 |
| `openPattern(patternId)` | `src/js/app.js` | 跨模块跳转并聚焦指定句型 |
| `validateSense(word, sense)` | `scripts/validate-content.mjs` | 校验义项 ID、字段、例句和状态 |
| `validatePattern(pattern)` | `scripts/validate-content.mjs` | 校验公式、operator、例句和规则引用 |
| `validateCrossReferences()` | `scripts/validate-content.mjs` | 防止词条、语法和句型引用不存在的 ID |

### 7.2 校验门禁

构建必须阻止以下问题：

- 任一词没有 `senses[]` 或任一义项没有例句。
- 义项 ID、句型 ID、语法规则 ID 重复。
- 例句出现未许可且未标记类别的词。
- `pattern.operators` 中出现 18 个 operators 之外的词。
- 词条引用不存在的句型，或句型引用不存在的语法规则。
- 已标记“人工审校通过”的内容仍含待定字段。

构建只给警告、不直接失败的情况：

- 一个词拥有过多义项或单个义项例句超过建议上限。
- 多个义项使用完全相同的例句。
- 句型公式已存在高度相似项。
- 例句虽然词汇合规，但尚未人工审校自然度。

### 阶段 D：发布与回归

1. 构建单文件。
2. 检查桌面与移动端长词卡、长句型公式和 Tab 导航。
3. 验证朗读、深链、学习进度和旧版数据兼容。
4. 输出各审校状态数量，不把“自动通过”表述为“语言学已核验”。

## 9. 风险与边界

1. **最大风险是内容正确性，不是前端技术。** 850 词逐义项补例句需要持续人工审校，不能一次批量生成后直接标为完成。
2. **义项不可从中文分隔符自动拆分。** 当前 199 条只是候选，像近义翻译、词性差异和真正多义必须区分。
3. **句型不是任意组合器。** `operator + thing` 在语法上可写，不代表所有搭配自然或符合 Ogden 的教学习惯。
4. **语法和句型必须共享数据引用。** 否则同一结构会在两个模块出现不同解释。
5. **旧数据需要渐进迁移。** 不建议一次性改完 850 条再看页面，应先用 operators 做完整垂直切片。
6. **例句数量不应成为质量指标。** 目标是覆盖有效义项和结构，而不是每个词机械凑固定条数。

## 10. 验收标准

### 功能验收

- 可通过“只看未学习”过滤所有已学习词。
- 多义词能分义项展示，每条例句可朗读。
- Grammar、Patterns、Communication 三个模块职责清晰。
- Patterns 可按功能和 operator 筛选，并可从词卡、语法规则互相跳转。
- 离线打开时所有模块正常工作。

### 内容验收

- 850 个词全部至少有 1 个明确义项和 1 条对应例句。
- 18 个 operators 的核心用法全部有人工作审校标记。
- 所有语法规则包含解释、适用条件、正例和限制／误区。
- 句型覆盖 18 个 operators 的主要结构，并包含否定、疑问、命令和扩展层。
- 所有例句通过词汇边界校验；例外词有明确类别和说明。

## 11. 变更总结
